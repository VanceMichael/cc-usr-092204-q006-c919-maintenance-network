# C919维修能力网络

本项目服务于维护C919机队构型、维修方案与基地保障能力。首次深度定检完成后，机队十二架飞机继续扩容；广州、湖南双基地与各通航机场实行“一地一策”——同一机型在不同站点只允许采用当时当地对该构型有效的方案、工卡、工具与人员组合，不能简单复制同一套工卡和备件清单。

## 领域事实

- 机队已形成广州和湖南双基地
- 保障网络覆盖各通航机场
- 机务团队首次完成该机型深度定检
- 机队规模十二架并继续扩容
- 各站点按一地一策运行

## 领域规则与代码

| 规则 | 模块 |
| --- | --- |
| 有效组合：跨基地运行只允许采用当时对该构型有效的方案/工卡/工具/人员组合；管理者可查看各地真实可承接的维修层级 | `src/effectivity.js` |
| 定检中遇适航指令升级：明确继续、追加还是退回；超出本站能力时给出异地支援候选 | `src/directives.js` |
| 拆换件与借用工具的数量和去向守恒，未闭环的借出/送校被列出 | `src/conservation.js` |
| 多人签署、夜间交接、离线补传、重复故障合并不破坏审计顺序 | `src/audit.js` |
| 某项能力暂停时立即找出受影响飞机与后续航班 | `src/impact.js` |
| 从一次放行追到工卡、工具、部件和签署证据 | `src/traceability.js` |

## 目录说明

- `contracts/` 保存交换数据的结构约定（JSON Schema）。
- `fixtures/` 提供去标识的领域样例：站点与策略、机队、方案/工卡/指令、资源、运行记录。
- `src/` 提供资料读取、领域规则与服务入口。
- `test/` 核对领域资料与规则行为。

## 本地检查

运行 `npm test` 可以检查当前资料与服务入口。

运行 `node src/server.js` 启动服务入口：

- `GET /health` 健康检查
- `GET /context` 领域上下文
- `GET /capabilities?at=YYYY-MM-DD` 各地真实可承接的维修层级
- `GET /releases/:id/trace` 放行证据追溯（样例：`RL-2026-0001`）
