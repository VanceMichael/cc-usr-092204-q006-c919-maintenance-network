# C919维修能力网络

本项目服务于维护C919机队构型、维修方案与基地保障能力。仓库保存领域资料、交换契约和可运行的服务入口，便于参与方在同一语义下协作。

## 领域事实

- 机队现有十二架飞机，已形成广州和湖南双基地
- 保障网络覆盖各通航机场
- 机务团队首次完成该机型深度定检
- 各站点实行“一地一策”：工卡适配与备件清单按站配置，不能简单复制同一套工卡和备件清单

## 管理对象

飞机构型、维修方案版本、适航指令、工卡修订、专用工具校准、放行人员授权、部件寿命与异地（跨站）支援，统一建模在 `fixtures/network.json`（网络快照）与 `fixtures/events.json`（审计事件流）两份去标识样例中，结构由 `contracts/` 下的契约约束。

## 关键业务规则（由 `src/invariants.js` 落实）

1. **组合有效性**：飞机跨基地运行时，每次工卡签署所用的（构型，方案版本，工卡修订，站点适配版）组合必须在发生时刻有效；方案与工卡修订均有生效窗口。
2. **指令升级处置**：执行中的定检遇到适航指令升级，必须记录“继续 / 追加 / 退回”处置，且处置在审计序列上先于放行。
3. **数量守恒**：拆换件与借用工具的来源、去向全程明确；从基线重放事件流必须回到当前快照（账实相符），任何环节不得凭空产生或消失。
4. **审计顺序**：事件按序号全序、记录时间单调；多人签署各自留痕，夜间交接记录双方，离线机场补传必须标记 `offline_backfill`，重复故障只合并不删除——均不得破坏审计顺序。
5. **授权与校准**：签署、拆换、放行人员的授权（站点/层级/角色）与工具校准在发生时刻有效；每件工具保管权唯一，外借期间不得在原地使用。
6. **部件寿命**：装机部件已用寿命不得超过寿命限制。

## 查询能力

- `src/impact.js` — 能力暂停时立即找出受影响定检、飞机与后续航班（`suspensionImpact`）；并给出各地真实可承接的维修层级（`effectiveCapabilities`：声明能力 × 未暂停 × 有有效放行授权）。
- `src/trace.js` — 从一次放行追到工卡、工具、部件与签署证据链（`traceRelease`）。

## 目录说明

- `contracts/` 保存交换数据的结构约定（领域上下文、网络快照、审计事件流）。
- `fixtures/` 提供去标识的领域样例。
- `src/` 提供资料读取、契约校验、不变量校验、影响分析、放行追溯与健康检查入口。
- `test/` 核对资料载入、契约符合性、不变量正反例与查询结果。

## 本地检查

运行 `npm test` 可以检查当前资料与服务入口。

## 服务接口

`node src/server.js` 后（监听 `127.0.0.1:8000`）：

- `GET /health`、`GET /context`、`GET /network`、`GET /events` — 资料读取
- `GET /impact?site=GA2&capability=LINE&from=2026-09-26T10:00:00%2B08:00` — 能力暂停影响
- `GET /capabilities?at=2026-09-26T11:00:00%2B08:00` — 各地真实可承接层级
- `GET /trace?release=REL-7001` — 放行追溯
